## Context for the LLM (why this existed)

**Two data paths during migration:**

| Path         | Source                                      | Consumer                                  |
| ------------ | ------------------------------------------- | ----------------------------------------- |
| Dev seed     | `regionSeedCatalog.ts` (10 `dev-*` regions) | `bun run seed`                            |
| Prod cutover | `regions.const.ts` (~34 real regions)       | `01-regions-from-const.ts` (once per env) |

**Config param files (`v2/configs/_*.ts`):**

- Generated when regions lived in `regions.const.ts` — each file is the **template** (part 1) for one checksum used in shareable map URLs
- `02-backfill-config-templates.ts` copied every entry from `v2/configs/index.ts` into `RegionConfigTemplate` so decoding no longer depends on committed TS files
- After backfill on all envs, the file archive is redundant; DB is the source of truth for historical checksums, and `upsertRegionConfigTemplate` handles new checksums on every region save
