# Map hover and selection across region modes

## Purpose

The region map pairs a sidebar list with map layers in Hinweise, QA, and Prüflisten. Hover and selection can start on either surface. This is the live wiring, plus the gaps.

## Directions

| Direction                  | Mechanism                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Status                        |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| List hover → map marker    | `ModeListItem` / `ModeDataTableRow` write `{ id, coordinates }` to `mode-list-store`. Off-screen items use `MapListHoverMarker` (clamped to the canvas edge). In-view **notes** paint a fill-only `${layerId}-highlight` disc under the icon (`noteHighlightCirclePaint`, same paint as selection); QA and Prüflisten still use the HTML ring on the point. `ModePanel` shows “Außerhalb des Kartenausschnitts” while `atEdge`. Map clicks call `clearHoveredListItem` so a list hover disc cannot linger on another pin. | Live in all three modes       |
| Map hover → list row       | `RegionMap` `onMouseMove`/`onMouseLeave` write a mode-prefixed id to `hoveredMapItemId` (no coordinates). `ModeListItem` / `ModeDataTableRow` apply `modePanelListItemHoveredClassName` when that id matches. Atlas/mask hits clear it. Does not write `hoveredListItem`, so the centroid HTML ring stays list-only. **Notes** also feed this id into `${layerId}-highlight`, so the pin gets the same disc as list hover.                                                                                                | Live in notes, QA, Prüflisten |
| Map click → selection ring | Click writes the `f` param. `UpdateFeatureState` syncs `selected` (never `hover`). QA paints a dedicated `${qaLayerId}-selected` inner ring; OSM/internal notes paint `${layerId}-highlight` (same disc as list hover, `id` **property** filter); Prüflisten paints status-colored geometry plus a selection halo, excluding the entry being edited.                                                                                                                                                                      | Live                          |
| List click → map selection | Row `onClick` calls `setFeaturesParam(mergeModeUrlFeature(…))`. Same `f` param and the same selected layers as a map click; the active row scrolls into view.                                                                                                                                                                                                                                                                                                                                                             | Live                          |

Pointer hover on a **map** feature is separate from the list HTML marker: QA uses `LayerHighlight` with `includeSelected={false}` so the accent inner ring and fill fade do not stack with `qa-layer-selected`. Notes pointer hover uses the same highlight disc as list hover (`hoveredMapItemId` in `noteHighlightFilter`). Review-list paints do not read `feature-state hover` (hitareas are `opacity: 0`); list hover still uses the HTML ring.

Notes in-view hover (list or map) and selection share `${layerId}-highlight` (`noteHighlightFilter` on selected and hovered ids). Off-screen notes and other modes still use the centroid HTML marker.

## Two highlight mechanisms

**MapLibre `feature-state`.** `RegionMap` diffs `queryRenderedFeatures` and calls `safeSetFeatureState`. Paint expressions read `['feature-state', 'hover']` / `selected`. Only layers from `useInteractiveLayers` participate. `safeSetFeatureState` no-ops when `feature.id` is missing. QA and review-list sources set `promoteId` to `id`; **notes sources set neither**, so feature-state on a note does nothing. Feature-state also cannot reach unloaded tiles.

**Filtered highlight layer.** Notes and Prüflisten match the GeoJSON `id` property (`['in', 'id', …]`). No `promoteId` required. Notes hover and selection share `${layerId}-highlight`. Prefer this for new notes/review work unless you specifically need QA’s fill/opacity fade.

Ids in the list store are mode-prefixed (`qa-${areaId}`, `note-${sourceId}-${id}`, `review-${id}`). List hover carries coordinates so the ring works for off-screen items. Map hover stores only the id (`hoveredMapItemId`) and never writes coordinates. `unhoverListItem(id)` only clears when `id` is still hovered, because `mouseleave` can arrive after the next `mouseenter`. Accents come from `modeIdentity[mode].accent`.
