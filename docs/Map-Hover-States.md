# Map hover and selection across region modes

## Purpose

The region map pairs a sidebar list with map layers in Hinweise, QA, and Prüflisten. Hover and selection can start on either surface. This is the live wiring, plus the gaps.

## Directions

| Direction                  | Mechanism                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Status                        |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------- |
| List hover → map marker    | `ModeListItem` / `ModeDataTableRow` write `{ id, coordinates }` to `mode-list-store`. Off-screen items use `ModeListHoverEdgeMarker` (clamped to the canvas edge). In-view **notes, QA, and Prüflisten** paint MapLibre highlight (`${layerId}-highlight` / halo layers) with the same paint as selection. `ModePanel` shows “Außerhalb des Kartenausschnitts” while `atEdge`. Map clicks call `clearHoveredListItem` so a list hover disc cannot linger on another pin. | Live in all three modes       |
| Map hover → list row       | `RegionMap` `onMouseMove`/`onMouseLeave` write a mode-prefixed id to `hoveredMapItemId` (no coordinates). `ModeListItem` / `ModeDataTableRow` apply `modePanelListItemHoveredClassName` when that id matches. Atlas/mask hits clear it. Does not write `hoveredListItem`, so the off-screen HTML edge disc stays list-only. Notes, QA, and Prüflisten also feed this id into the highlight filter, so the map feature gets the same highlight as list hover.             | Live in notes, QA, Prüflisten |
| Map click → selection ring | Click writes the `f` param. `UpdateFeatureState` syncs `selected` (never `hover`). QA paints `${qaLayerId}-highlight` (same inner ring as hover, `id` filter); OSM/internal notes paint `${layerId}-highlight` (same disc as list hover, `id` **property** filter); Prüflisten paints status-colored geometry plus a selection halo, excluding the entry being edited.                                                                                                   | Live                          |
| List click → map selection | Row `onClick` calls `setFeaturesParam(mergeModeUrlFeature(…))`. Same `f` param and the same selected layers as a map click; the active row scrolls into view.                                                                                                                                                                                                                                                                                                            | Live                          |

Notes, QA, and Prüflisten in-view hover (list or map) and selection share one highlight filter (`notesHighlightIds` / `qaHighlightIds` / `reviewHighlightIds`). Off-screen items still use `ModeListHoverEdgeMarker` at the map edge.

## Two highlight mechanisms

**MapLibre `feature-state`.** `RegionMap` diffs `queryRenderedFeatures` and calls `safeSetFeatureState`. Paint expressions read `['feature-state', 'hover']` / `selected`. Only layers from `useInteractiveLayers` participate. `safeSetFeatureState` no-ops when `feature.id` is missing. QA and review-list sources set `promoteId` to `id`; **notes sources set neither**, so feature-state on a note does nothing. Feature-state also cannot reach unloaded tiles. Atlas layers still use `LayerHighlight` (feature-state hover/selected). QA fill/outline opacity is only feature-state (0.7 otherwise). Map hover uses `LayerHighlight`. List hover sets the same `hover` feature-state. Selection paints `${qaLayerId}-highlight` / `-highlight-outline` (transparent body already comes from `selected` feature-state).

**Filtered highlight layer.** Notes, QA, and Prüflisten match feature ids (`['in', 'id', …]` or `['to-string', ['id']]` for QA vector tiles). Notes hover and selection share `${layerId}-highlight`. Prefer this for new mode work unless you specifically need atlas `LayerHighlight`.

Ids in the list store are mode-prefixed (`qa-${areaId}`, `note-${sourceId}-${id}`, `review-${id}`). List hover carries coordinates so the ring works for off-screen items. Map hover stores only the id (`hoveredMapItemId`) and never writes coordinates. `unhoverListItem(id)` only clears when `id` is still hovered, because `mouseleave` can arrive after the next `mouseenter`. Accents come from `modeIdentity[mode].accent`.
